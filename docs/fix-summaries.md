## 2026-09-16 — Production deployment checklist

`EMAIL_WEBHOOK_ENDPOINT_TOKEN` is generated by the project owner. Resend does not issue this token. Generate one with:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

Register this webhook URL in Resend after replacing the placeholder with the generated value:

```text
https://admin.gologs.com.ng/api/webhooks/v1/email/generated_value_here
```

Required Vercel environment variables:

```env
APP_ENV=production
ADMIN_ORIGIN=https://admin.gologs.com.ng
EMAIL_PROVIDER=resend
EMAIL_DELIVERY_ENABLED=true
EMAIL_FROM=GO Admin <admin@gologs.com.ng>
RESEND_API_KEY=...
EMAIL_WEBHOOK_SIGNING_SECRET=...
EMAIL_WEBHOOK_ENDPOINT_TOKEN=...
```

The Vercel build error was caused by deployment of old commit `334d25d`, which did not include Tailwind’s Linux native package. The package was added explicitly and pushed in commit `dc8be9a`. Redeploy the latest `main` branch and clear the Vercel build cache once.

Launch verification checklist:

- Add the webhook in Resend.
- Redeploy the latest `main` commit.
- Update the public newsletter form to call the admin subscription endpoint.
- Send a real test email and confirm the webhook appears in `provider_events`.
- Test duplicate webhook delivery and bounced-email handling.
- Confirm all Supabase production variables are set in Vercel.

Resend uses signed, at-least-once webhook delivery, so duplicate event handling is required. References: [Resend webhook guide](https://resend.com/docs/webhooks/introduction) and [Svix verification guide](https://docs.svix.com/receiving/verifying-payloads/how).

## 2026-09-16 — Production Resend webhook receiver

Implemented and pushed in commit `da36610`.

Supported Resend events:

```text
email.sent
email.delivered
email.delivery_delayed
email.bounced
email.complained
email.opened
email.clicked
```

The receiver verifies Svix/Resend signatures against the raw request body, rejects stale requests, protects the endpoint with a secret token, validates payloads, stores provider events idempotently, and queues normalization work. Resend retries failed webhook requests and uses at-least-once delivery, so duplicate event IDs are acknowledged safely without creating duplicate records.

Production endpoint format:

```text
https://admin.gologs.com.ng/api/webhooks/v1/email/<EMAIL_WEBHOOK_ENDPOINT_TOKEN>
```

References:

- [Resend webhook documentation](https://resend.com/docs/webhooks/introduction)
- [Svix webhook verification guidance](https://docs.svix.com/receiving/verifying-payloads/how)
